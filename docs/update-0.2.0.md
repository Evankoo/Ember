# v0.2.0：通用设置与本机执行环境

本轮提炼的是完整 GStudio 的通用设置流程，不复制个人电脑配置、内部 Agent 策略或飞书、AList、NAS 依赖。基础 Skill 仍只有 `gstudio-init` 1.0.2 与 `gstudio-core` 1.2.0；运行依赖仍只有 PyYAML。

## 新增的公开范围

- 设置顶部直接显示已保存默认软件、类型、路径、就绪状态及修改方式；有效配置的编辑区按需展开，空白、不可用和不可读状态分别说明。
- 本机软件可只读查找或手工添加 `.app` / 命令行程序；下拉框来自用户确认清单，不固定 Codex / OpenCode。查找结果不是已保存项，也不自动选择默认。
- 草稿、检查通过但未保存、保存与取消修改分开；统一浅色按钮和可见边框，不改变其他页面或业务生命周期。
- 本机清单只写 `~/.config/gstudio-core/executors.json`，保存使用私有权限、备份、锁和版本冲突检查；不可读文件不按空文件覆盖。
- 核对上下文后，可单独复制或明确“复制并打开”。浏览器复制失败不打开；打开接口只接收当前已保存软件 ID、配置版本和确认，重新校验路径，不接受提示词、任意命令或模型参数。
- macOS 打开应用或新的 Terminal；Linux 命令行程序需要现有图形终端。用户自行粘贴、确认并发送，Core 不调用模型、不自动提交，不把打开软件视为任务执行或完成。

软件路径检查不验证账号、模型或程序来源；只登记你信任的软件。第三方客户端自身的启动行为由其管理。设置页只显示 Core 真正安装的两项基础 Skills，不显示内部系统的“28 项待配置能力”，也不提供私人 Agent 维护按钮。

## 已有安装

更新应用包后，继续使用原 `--workspace` 启动，不重新 `init`，不覆盖已有工作区或其中的规则、Skill、任务和交付。若要采用新版规则正文，先备份、比较本地修改并单独确认合并范围。

旧 Core 未登记软件时，新设置从空清单开始；不会复制其他系统的配置或创建机器文件。只有用户明确保存才写 Core 私有清单。旧版已有效的工作区契约和不含版本号的 Skill 登记仍可读取。

`v0.1.0` / `v0.1.1` 发行保留。当前公开接口、安全边界和可选真实浏览器测试见 `api.md`、`../SECURITY.md` 与 `../README.md`。
