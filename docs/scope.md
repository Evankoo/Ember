# 开源版范围

本仓库是 GStudio 的开源单机版。它沿用完整版的工作方式：任务卡、项目说明、输入与交付分开、人工确认后才定稿。实现是为单机重新写的，示例数据完全虚构。它不是完整版的等价副本，也不能与完整版互相同步或迁移数据。

## 包含

- **工作台**：任务台、项目视图、任务检视、资料浏览、设置五个常驻页面，加上项目（project）和系统（system）两类工作区，以及独立任务。
- **任务卡**：Markdown 正文按“任务目标、任务描述、当前结果、下一步、执行日志”排列；可登记实际执行工具和使用的 Skill；任务线只引用关联任务，不搬动原任务。
- **资料与交付**：输入快照带来源、大小和 SHA-256；已有资料可登记为引用而不复制；草稿与正式交付分开，确认后复制校验到正式目录并完成任务。
- **AI 上下文**：从所选任务构造给 AI 的上下文，可单独复制，或明确确认后打开本机已登记的软件；不调用模型，不自动发送。
- **三个 Skill**：`gstudio-init` 分步安装并建立真实首任务，`gstudio-core` 在任意目录续接日常工作，`gstudio-project` 查重并确认后建项目。
- **本机登记**：默认工作区记在 `~/.config/gstudio-core/workspace.json`，本机软件清单记在 `~/.config/gstudio-core/executors.json`；两者都不在工作区里。

## 与完整版的差异

| 方面 | 完整版 | 开源版 |
| --- | --- | --- |
| 工作位置 | 共享网络存储与多台电脑同步 | 本机工作区，同一工作区一个服务进程 |
| 项目说明 | 项目类型、业务分类、能力配置，可接外部知识库 | project / system 两类，本地 Markdown 说明 |
| 任务整理 | 周期整理、控制任务与逐项执行回执 | 手动选择任务、构造建议、保存人工报告 |
| AI 执行 | 多个执行器、运行 Agent 与能力授权 | 复制上下文，或确认后打开已登记软件 |
| 资料摄入 | 外部文件快照、外部引用与归档路由 | 界面新增文字最多 1 MiB，引用限工作区内文件 |
| 归档 | 归档中心、归档队列与确认删除 | 不包含；旧工作区的归档文件原样保留 |
| 结构修订 | 确认后合并、拆分任务，重开正式交付 | 可准备建议；不合并拆分，不重开正式交付 |

后续增加能力时，会同时更新系统规则、校验、页面和示例，并记入 [更新记录](../CHANGELOG.md)。

## 不会进入本仓库

真实任务与交付、长期记忆、真实项目配置、机器配置、网络存储地址、登录配置、令牌、业务资料、运行日志和用户安装的第三方 Skill。示例来自独立编写的虚构材料，不是对真实数据脱敏。

## 如何验证

`tests/` 覆盖存储、HTTP、本机登记、软件设置、初始化和建项；`test_browser.py` 可选用真实 Chromium 检查页面。`gstudio check` 验证当前工作区的数据与规则。检查通过只说明满足本页所述范围，不代表与完整版等价。
