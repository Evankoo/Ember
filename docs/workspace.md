# 工作区与使用说明

安装程序和工作数据相互独立。初始化建立以下相对路径：

```text
AGENTS.md           系统操作规则正本
SOUL.md             工作原则
MEMORY.md           空白的长期上下文记录
RESOLVER.md         当前工作区相对路径
WORKBENCH_DESIGN.md  统一设计约定
.agents/skills/     初始化、日常入口、建项三项 Skill
skills/             Skill 登记与路由
templates/          任务卡创建模板
config/             项目/系统注册与工作区名称
projects/           项目说明 Markdown（总览 / 工作位置与入口 / 范围与要求 / 当前阶段 / 时间线）
tasks/active/       活跃、等待确认或阻碍中的任务卡
tasks/completed/    已完成任务卡
inputs/             每项任务的输入快照
delivery/draft/     草稿交付
delivery/formal/    正式交付
inbox/              本地待分类来源
reports/            已保存的检视报告
.gstudio/           重要事项与 Inbox 标签
```

可以关闭服务后编辑 Markdown，再重新启动读取。编辑时保留必需的 frontmatter 和四个必需正文标题（任务目标、任务描述、当前结果、执行日志）；下一步按需添加，执行日志保持最后；错误卡片会明确报错，不会被默默当成不存在。未识别的旧系统数据应先人工核对，不要直接整库拷入。

同一目标的续接继续原任务；有独立目标、验收结果或后续生命周期的维护工作另建任务卡，不能把原发布卡当作所有维护工作的永久容器。两者都归属于实际项目，不因更换执行工具重复建卡。

通过 `gstudio-init` 引导建立新工作区时，先登记 `GStudio` 系统及真实安装首任务；安装选择放在 inputs，隔离测试结果形成草稿，人工验收前保持 active。底层 `gstudio init` 仅建立空结构。业务项目由 `gstudio-project` 查重、完整方案确认后登记；不因调用另一项 Skill 重复创建安装任务，也不自动改变旧任务归属。详见 [初始化流程](initialization.md)。

## 项目与工作目录

项目可以登记本机工作目录（`config/projects.json` 的 `locations`，绝对路径）。在这些目录或其子目录里协作时，`gstudio which-project` 会返回对应项目，日常 Skill 据此续接该项目的任务；查不到时由用户确认，不按目录名猜。用 `gstudio project-location <项目> <目录>` 登记，`--remove` 移除；只改登记，不改项目说明正文。工作目录本身留在原位，不搬进工作区。

项目可以有一个分类（`category`，20 字以内的单行文字），由用户自己命名，用于项目视图和侧栏分组；不影响项目类型、任务归属或生命周期。新建项目时可填写，已有项目用 `gstudio project-category <项目> <分类>` 设置，`--clear` 清除。侧栏的收藏只保存在当前浏览器，不写入工作区。

## 输入与交付

界面“添加资料”只新增 UTF-8 文字文件，可选输入、草稿或已有资料引用。新增文字内容受单次 1 MiB 请求限制。同名文件不可覆盖；变更材料应另起名字。图片、PDF 等已有草稿文件可在关闭服务后放入对应任务交付目录，并同步任务卡的 artifact_mode、delivery.state/folder、outputs 和 Quick Navigation，随后校验；资料浏览提供下载。输入快照需要在任务卡 `inputs.items` 登记相对路径、大小、SHA-256、来源和用途，校验会拒绝缺失或变更的快照；不要只放文件而省略登记。文本预览仅支持可读文字格式。

示例输入登记可以引用工作区内已有输入或正式交付，不复制来源。界面支持通过已有文件路径登记新引用，校验位置且不复制。输入登记使用 `storage`、`size`、`source_locator`、`source_environment`、`sha256`、`added_at` 等字段。

正式交付需要用户确认，复制并校验任务的整个草稿目录，再移动任务卡到已完成。已有正式目录会阻止覆盖。原草稿保留用于追溯；已完成任务在此最小版中不可直接改写或重新打开。

无文件成果的 `none/system/archive/external` 任务在记录结果后可单独确认完成，不创建空交付文件。`delivery` 任务必须走正式交付。交付记录使用 `delivery.state: draft|final` 与 `delivery.folder`；只有真实文件出现后才建立交付目录和 Quick Navigation；任务线会预建非空说明与关联索引，是明确的例外。

## Inbox 与旧资料

把真实待分类包放入 `inbox/`。标签 `未分类 / 处理中 / 待归档 / 可删除` 由内容指纹关联，不移动来源。工作台不会扫描系统 Downloads。

标签是资料状态元数据；`待归档` 或 `可删除` 的名字不授权任何操作。v0.3.0 不包含归档中心、归档复制接口或永久删除操作，也不自动把标签转换成文件处理动作。

已有工作区的 `archive/` 与 `.gstudio/archive-records.json` 留在原位置，不删除、不迁移、不解析旧回执。旧任务中明确登记的归档文件引用仍可作为输入读取；未被引用的归档文件不进入资料索引。正式交付与任务完成流程不变，详见 [更新记录](../CHANGELOG.md)。

## 检视与外部 AI

任务台和任务检视生成文字上下文，不连接模型。可单独复制，或在设置中确认本机默认软件后明确“复制并打开”；Core 只打开已保存程序，用户自行粘贴并发送，不把业务文字作为启动命令。软件配置不在工作区中，不改变任务状态。外部返回的建议需要人工判断；保存报告只记录文本，不执行合并、拆分或删除。

新任务线需要至少两项同项目的普通任务，只引用任务 ID，不搬动原任务或文件。请在明确理解关联后创建。

## 使用限制

同一工作区同时只运行一个服务进程；第二个服务会被工作区锁拒绝。请求在进程内串行写入并使用原子文件替换。这不是共享盘或多人并发系统，未提供跨文件断电事务恢复。修改数据前备份整个工作区。

示例报告与时间线日期是固定的虚构历史。项目视图的“近 30 天完成”按当前时间与任务 updated_at 的完整时区时间计算滚动 30 天窗口，历史任务可能只在完整任务列表中出现。
