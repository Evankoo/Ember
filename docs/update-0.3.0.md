# v0.3.0 发布范围调整

归档中心尚不作为稳定的公开能力。本版从后续公开源码和安装包移除归档导航、页面与专用样式、归档复制接口、回执实现及虚构归档示例，而非只隐藏入口。任务、输入、草稿、正式交付、检视、软件设置与明确复制打开流程保持可用。

## 已有工作区

1. 关闭原服务，先自行备份工作区和安装环境，再安装 v0.3.0。
2. 不重新初始化非空工作区；初始化 Skill 不执行升级或重置。
3. 原 `archive/` 文件和 `.gstudio/archive-records.json` 留在原位置。本版不扫描整个归档目录、不解析旧回执、不删除或迁移这些数据。
4. 旧任务已明确登记的工作区内归档文件仍可作为输入引用读取，路径越界和符号链接仍被拒绝。未引用的归档文件不再出现在资料索引。
5. Inbox 标签只是资料状态元数据，不触发归档、复制或删除。正式交付和任务完成流程不变。

旧工作区内的系统规则和 Skill 不会被程序自动改写；使用外部 Agent 前应核对旧规则与新版本能力的差异，不能按旧归档说明调用已移除接口。需要更新这些规则时，单独确认范围并保留原文件。

## 接口变化

- `POST /api/archive` 返回 404，不写入工作区。
- `Workspace.archive_item` 不再存在。
- snapshot 不再返回 `archives`、`archive_records` 或 `kind:archive` 文件。
- `artifact_mode: archive` 与旧输入的 `storage: archive` 仅保留历史卡片读取兼容，不代表可执行归档能力。
- 旧 `#archive` 链接显示“页面不存在”，可返回任务台；没有隐藏的归档界面。

新初始化 Skill 为 `gstudio-init` 1.1.0，日常入口为 `gstudio-core` 1.3.0。工作区规则明确：同一目标继续原任务；有独立目标、验收结果或生命周期的维护工作另建任务，原发布卡不是永久容器。

v0.2.0 及更早的发行版和 Git 历史保留，不做历史重写或旧包删除。此调整只属于 GStudio Core，完整 GStudio 的归档中心不受影响。
