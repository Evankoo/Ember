# 最小版的提炼范围

GStudio Core 是可安装的本地工作台。它保留完整系统的基础数据关系与视觉语言，重新组合成单机运行所需的小型实现。

## 发布清单

- `src/gstudio_core/cli.py`：显式初始化、校验、启动。
- `src/gstudio_core/bootstrap.py`、`templates/`：可移植系统入口、规则与任务卡模板。
- `src/gstudio_core/skills/gstudio-init/`：首次安装引导、标准库安装脚本和验证。
- `src/gstudio_core/store.py`：任务卡、项目、输入交付、检视报告和本地归档。
- `src/gstudio_core/server.py`：只监听回环地址的 HTTP 服务。
- `src/gstudio_core/web/`：六个常驻页面、项目与任务详情、共享样式、标志与字体。
- `src/gstudio_core/examples/workspace/`：完全虚构的可写示例。
- `pyproject.toml`、测试、文档与许可证：安装和维护的最小支撑。

## 来源语义

| 原系统职责 | 最小版保留的语义 |
| --- | --- |
| 工作台设计规范与共享样式 | 暖纸色、深色侧栏、标题字体、留白、阅读顺序与响应式布局 |
| `gstudio_task.py` 与任务卡标准 | Markdown 正本、明确目标、当前结果、下一步和日志 |
| 项目视图与项目工作区 | 项目拥有任务；任务、交付、输入是同级场景 |
| 任务输入与交付流程 | 输入和交付分离、引用已有资料、拒绝覆盖、确认正式交付 |
| 归档 Inbox 与归档回执 | 标签只改元数据；明确确认后复制、校验、保留来源 |
| 任务检视与共享提示词 | 从选定记录构造上下文；报告本身不授权结构或生命周期变化 |

完整系统的机器路径、共享盘锁和外部适配器不能直接作为公共安装依赖，因此用显式本地工作区替代。这个最小版不承诺与完整系统互相同步，也不是完整系统数据库的自动迁移器。

## 不发布的内容

生产仓库历史、真实任务与交付、长期记忆、真实项目配置、机器配置、NAS 地址、隧道和登录配置、令牌、业务资料、运行日志、应用缓存、用户安装的第三方 Skills 均不进入本仓库。

示例来自独立虚构展示材料，并转换成真正的工作区文件；没有从真实任务库抽样脱敏。新仓库从新的 Git 历史开始。

完整的逐项核对与明确保留的差异见 [系统对照](system-alignment.md)。初始化不是生成网页演示：它会建立可以写入、重启回读、校验并正式交付的独立工作区。
