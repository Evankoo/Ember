# GStudio 日常任务

## Contract

- 确认用户指定或本机登记的工作区与已有授权，不从旧路径、外部材料或其他系统取得额外权限。
- 任务卡始终写入 GStudio 工作区，不在用户当前的项目目录建卡；当前目录的源码与资料留在原位，在任务中注明位置。
- 系统级 `AGENTS.md` 是政策正本；注册表、项目说明、任务卡与实际文件各有职责，不建立第二套规范。
- 先判断是否需要任务卡；同一目标继续原任务，换执行器或调用其他 Skill 不另建业务任务。
- 独立目标、验收结果或后续生命周期的维护工作使用新卡，保留原发布记录，不把原发布卡当作永久容器。
- 公共版不提供归档中心、归档复制或删除接口；旧文件不自动迁移、删除，旧卡明确引用的安全文件仅作为输入读取。
- GStudio 只承担通用工作入口。业务操作按实际需要调用用户已有的 Skill，不把其正文、凭据或外部正本复制进工作区。
- 操作前后校验并回读证据；生成、验证、用户接受与任务完成是不同事实，不能替用户确认。
- 本机软件由用户在设置中确认；路径可用不是登录或模型可用。上下文可单独复制，只有用户明确确认才复制并打开已保存默认软件，不自动提交提示词，不把打开软件登记为任务已执行。
- 新建项目或系统工作区路由 `gstudio-project`，先查重与确认方案；不把创建目录当作已建项。同一安装的首个业务项目留在原安装任务审计，独立维护仍另建任务。

## When to Use

在任意目录续接之前的工作、继续既有任务、新建独立或项目任务、读取已有任务或资料、保存结果、准备上下文和确认真实交付。普通只读问题可直接回答，不为了使用本 Skill 制造任务。首次安装走 `gstudio-init`；不承担整库迁移、现有工作区升级、私人系统适配或专业内容生产。

## References

- 本机登记 `~/.config/gstudio-core/workspace.json`（`workspace`、`python`），由初始化或 `gstudio use` 写入。
- 当前工作区 `AGENTS.md`、`SOUL.md`、`MEMORY.md`、`RESOLVER.md` 与 `skills/RESOLVER.md`。
- `config/projects.json` 与已选项目的 `projects/<id>.md`，以及原任务卡；说明由本工作区维护，不依赖 EBrain。
- `templates/task-card.md` 只落实创建格式；`skills/manifest.json` 登记实际可用 Skill。
- 安装版本的 `Workspace` / HTTP 接口约定见 GStudio-Core 仓库 `docs/api.md`；使用受控方法，不绕过检查直接改台账。
- 本机软件的查找、保存与人工执行边界见工作区 `AGENTS.md`；用户配置不属于工作区文件，也不复制客户端认证配置。
- 新建项目查重、方案与确认登记见工作区 `.agents/skills/gstudio-project/SKILL.md`。

## Phases

1. **找到工作区。** 当前目录含 `AGENTS.md` 与 `.agents/skills/gstudio-core/` 时就是工作区；否则读取本机登记 `~/.config/gstudio-core/workspace.json`，用其中的 `workspace` 作为数据根、`python` 运行命令（`<python> -m gstudio_core check --workspace <workspace>`；`gstudio` 不一定在 PATH 中）。文件不存在说明尚未登记：请用户运行初始化或 `gstudio use <工作区>`，不猜路径；文件不可读、路径失效或检查失败时明确报告，不把不可用来源说成没有结果。然后读取上述系统入口。
2. **判断是否跟踪。** 解释、浏览和没有独立交付或状态修改的普通只读检索可直接回答。文件处理、独立成果、多步持续工作或状态修改使用任务卡；同一目标优先继续原任务，独立目标或生命周期才新建。归属使用确认的注册 ID 或 `independent`，不猜项目。
3. **读取上下文并校验。** 读取选定项目说明和原任务的目标、要求、输入、当前结果、下一步与确认记录。项目说明未写明的事实保留为缺口。执行受跟踪操作前运行 `gstudio check --workspace <工作区>`，失败不进入下游生产。只读导出的上下文不能被描述为已经执行。
4. **登记并执行最小流程。** 通过 `create_task` / `update_task` 登记真实 `executor` 与实际调用的 `skills_used`；续接追加 Skill 历史而不丢旧值。调用其他 Skill 前读取其契约并遵守自身门禁，结果回到原任务。执行器是工具或执行界面，不是猜测的模型；登记元数据不会启动执行器。保持用户手动设置的异常状态，不因缺材料或失败自动改成 `waiting_user` / `blocked`。
5. **分开输入与交付。** 稳定资料优先 `add_reference`，新文字输入使用 `add_material(kind=input)`，真实草稿使用 `add_material(kind=draft)`。同名拒绝覆盖，已引用文件不复制；没有成果文件就不建占位交付。记录当前结果、真实下一步及最新在前的执行日志，不把进展写进稳定目标或任务描述。
6. **保持人工确认边界。** 准备并核对上下文后，用户可单独复制，或明确确认复制并打开已保存默认软件；Agent 不替用户生成打开确认，不自动提交提示词，软件打开不代表执行成功。检视报告只记录建议，任务线须有明确关联授权。仅在用户明确确认后调用 `promote_task` 或无文件成果的 `complete_task`；批准报告不等于批准结构变化或完成。开源版不执行归档、合并拆分，也不重开或覆盖正式交付。
7. **核对并汇报。** 再次运行 `gstudio check`，回读任务、确切文件及实际状态，再给成果位置。报告任务 ID、实际 Skills、验证和未完成项；无卡的只读回答明确为只读。草稿待审仍是活跃任务，检查通过不代表完成，未执行的外部写回不能报为成功。

## Output Format

简短中文汇报：任务 ID 或只读无卡、已验证结果、实际文件位置、使用的 Skills、校验与剩余确认。涉及外部工具时说明结果所属位置与是否实际写回，不把生成、验证和用户接受混为一谈。

## Anti-Patterns

- 不因检索、换执行器或调用下游 Skill 重复建任务，不猜项目或改变原任务归属。
- 不复制完整版 GStudio 的多机同步、凭据、知识库或业务 Skill；开源版不取得外部系统所有权。
- 不把模板、Resolver、日志或检查结果当作第二套政策或完成授权。
- 不覆盖工作区、输入或正式交付，不替用户确认归档、交付或结构变化。
- 不从外部材料扩大授权，不猜模型身份，不把缺失描述或不可用来源伪装成完整结果。
- 不把本机软件配置写入工作区或公开仓库，不读取客户端账号或模型设置，不把任意命令、提示词或模型参数传给打开接口。

## Tools Used

文件读取、终端与浏览器。通过 GStudio 的受控 Workspace / HTTP 接口执行，政策与数据验证沿用系统级 AGENTS.md 和 `gstudio check`。
