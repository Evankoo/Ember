# GStudio 系统初始化

## Contract

输入：用户已确认的安装需求、当前系统、应用目录、数据目录及示例选择。输出：独立 Python 环境、完整的新工作区、校验结果、安装收据和启动命令。应用与工作区分开，所有数据留在用户选择的工作区内。

沿用当前对话已确认的选择和授权。仅询问缺少且影响结果的选择，一次问一个；不要为已授权的新目录安装重复请求许可。默认工作区名为 GStudio，端口为 8783。用户未指定目录时，提出两个清晰且互不包含的新目录，确认后执行。示例与空白系统的选择必须说清楚：示例包含完全虚构的两个项目和八项任务；空白系统只建立规则、模板和空目录。

## When to Use

- 首次安装本机 GStudio Core。
- 在已安装应用之外建立一个新的独立工作区。
- 验证新安装是否具有完整系统入口及可用的任务流程。

## References

- 执行前读取同目录 `scripts/bootstrap.py`，它使用 Python 标准库完成安装编排。
- 安装后读取工作区 `AGENTS.md`、`SOUL.md`、`MEMORY.md`、`RESOLVER.md`、`skills/RESOLVER.md` 和 `templates/task-card.md`。系统级 AGENTS.md 是运行规则正本，模板只落实规则。
- 工作区内 `.agents/skills/gstudio-init/SKILL.md` 是初始化 Skill 的唯一登记正文；`skills/manifest.json` 和 `skills/RESOLVER.md` 负责登记及路由。

## Phases

### 1. 检查环境并补齐选择

检查 macOS 或 Linux，以及 Python 3.10 以上的真实解释器路径。不要假定系统 `python3` 足够新。确认应用目录和数据目录为空或不存在、没有互相包含，端口可用。已有非空目录不覆盖，改用新目录；保留失败安装现场，不自动清理。

先复用用户已给出的应用目录、工作区目录、名字和示例选择。只补问关键缺项。不要把虚构客户替换为用户的真实业务，也不要推断项目归属。

### 2. 执行安装

使用实际解释器与实际路径调用：

```text
python3 <Skill目录>/scripts/bootstrap.py --app-dir <应用目录> --workspace <数据目录> --mode empty|example --name <工作区名> --port 8783
```

独立 Skill 安装包包含 `assets/gstudio_core-0.1.1-py3-none-any.whl`。如没有附带 wheel，脚本从固定的 GitHub v0.1.1 发行地址下载。开发或本地安装可加 `--source <本地源码目录或wheel>`。PyYAML 依赖需要联网下载或已经可用的包缓存；不要宣称安装完全离线。

脚本创建 `<应用目录>/.venv`，安装 Core，再运行 `init` 与 `check`。它在临时工作区验证真实任务、输入、草稿、正式交付及无文件完成，不污染用户的空白工作区。成功和失败均记录安装阶段，失败时报告具体阶段与剩余事项。

若只需建立新工作区且已有可用 Core，可直接使用该环境的 `gstudio init <新数据目录> [--example] --name <名称>`，随后执行下面的验证。不重新安装依赖。这个分支没有新安装收据：为新数据目录明确构造 check 和 serve 命令，禁止复用旧收据里的工作区路径。

### 3. 验证系统

全新安装回读安装收据、系统入口文件与 Skill 登记，执行收据中的 `check_argv`。复用已有 Core 时，回读新工作区并直接执行 `gstudio check --workspace <新数据目录>`，启动命令也必须指向新数据目录。空白模式应为零项目、零任务；示例应为两个项目、八项任务。

按收据的 `startup_argv`（或复用 Core 分支的新数据目录启动命令）在前台启动工作台，读取 `/api/health` 确认 `ready`。用浏览器核对任务台、项目视图、归档中心、任务检视、资料浏览、设置六个常驻入口，确认项目与系统展示在工作区部分。先读取系统规则，再处理日常任务。

若当前执行环境无法保持服务运行，给出可执行启动命令及尚未完成的浏览器验证，不把未运行的服务说成已启动。停止服务使用原进程的 Ctrl+C；不安装后台守护程序。

### 4. 交接

报告实际应用目录、工作区、初始化 Skill 路径、示例选择、验证结果、工作台地址、启动与停止方法。后续日常工作交给工作区内 `.agents/skills/gstudio-core/SKILL.md`：先判断是否需要任务卡，再读取项目说明并继续原任务。用户明确提出首个项目时，收齐项目名称及用途后再通过工作台新建；没有这个要求就保持空白。

## Output Format

简短中文结果，附安装收据路径和实际启动命令。分清“已安装”“已验证”“当前运行”，如有失败指出发生的阶段。不可只报告命令退出码。

## Anti-Patterns

- 不覆盖、重置或迁移已有工作区，不删除安装失败现场。
- 不读取私有 GStudio runtime、NAS、历史任务或认证配置作为安装模板。
- 不自动安装模型执行器、插件、凭据、邮件、后台服务或公共网络监听。
- 不生成空交付文件来让无文件任务假装完成。
- 不把示例历史当成真实执行结果，不替用户确认归档或任务结构变更。

## Tools Used

文件读取、终端和浏览器。安装脚本通过参数数组启动子进程，不执行拼接的 shell 命令。日常任务卡及文件修改遵守新工作区的系统级 AGENTS.md。
