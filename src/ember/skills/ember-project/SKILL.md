# 余烬项目建项

## Contract

只在用户已选择的余烬工作区操作。`AGENTS.md` 是规则正本，系统目录 `config/projects.json` 是登记，文档库 `项目/<id>/项目看板.md` 是独立说明。复用已有 `Workspace.create_project`，不建立第二套项目格式。`project` 是业务项目，`system` 是系统工作区；`independent` 不是项目。可选的 `locations` 是该项目在本机的工作目录（绝对路径），AI 在这些目录里协作时据此对应项目；可选的 `category` 是用户自己起的分类名（20 字以内），只用于项目视图和侧栏分组，不改变类型、权限或任务归属；说明正本采用“总览 / 工作位置与入口 / 范围与要求 / 当前阶段 / 时间线”骨架。

查重和方案阶段只读。登记必须获得用户对名称、ID、类型、用途与说明的明确确认；不猜业务事实。首次引导中的余烬系统项目和首个业务项目属于原安装任务，日后独立建项按 `ember` 判断跟踪范围，不为查重或调用本 Skill 再制造任务。

首次教学由日常 Skill 创建“余烬首次使用”任务并取得用户对任务卡的 OK 后，再进入本 Skill。用户确认练习方案后，完成查重、建项和回读，将真实 `ember-project` 使用记录留在这张卡；不依赖安装脚本预建任务。初始化向导之后可能从本库移除，本 Skill 继续保留并可独立使用。

## When to Use

- 首次安装时解释并建立余烬系统维护入口。
- 用户确认要建立第一个或后续业务项目、系统工作区。
- 首次引导中，用户检查对话任务卡并反馈 OK 后，确认建立一个用途明确的简单练习项目。
- 为明确的新建需求准备只读建项方案；已有项目优先复用。
- 用户确认某个本机目录属于已有项目时，登记或移除该工作目录。
- 用户确认已有项目的分类时，设置或清除该分类。

## References

- 当前工作区 `AGENTS.md`、`RESOLVER.md` 与 `skills/RESOLVER.md`。
- 系统目录 `config/projects.json`、文档库现有 `项目/<id>/项目看板.md` 和跟踪任务。
- 同目录 `scripts/project.py`：只读方案、同名/ID 冲突检查与确认登记；使用安装应用的 Python。
- 日常任务与跟踪判断见 `ember`，首次安装编排见 `ember-init`。

## Phases

1. **读取工作区与原任务。** 运行 `ember check --workspace <系统目录>`，读注册表、已有说明与跟踪任务；不可读时停止，不当作零项目。
2. **收齐缺项。** 沿用已确认信息，只补问名称、用途、业务/系统类型、实际范围、分类及本机工作目录中的关键缺项；分类沿用已有名称或留空，不替用户新造；没有固定目录可留空，不猜路径。已有同 ID 或同名项目时说明差异，请用户决定复用或修订，不覆盖。

   首次引导的练习项目可建议名称“余烬练习项目”、ID `ember-practice`、`kind:project`，用途为熟悉项目说明与任务管理，范围为首次使用练习；没有外部资料目录就保持 `locations:[]` 和未分类。独立说明明确写练习用途，不编造客户或业务事实。用户确认完整方案后才登记，练习项目保留供用户后续使用，不因测试结束自动删除。用户有真实项目时以其确认信息替换；用户跳过则不创建。建项仍记录在原安装任务，不移动该任务，也不额外制造测试任务。
3. **展示方案。** 给出小写 ID、名称、`kind`、用途/范围、工作目录 `locations`、分类 `category`、独立说明、实际写入位置与边界。只读调用 `project.py --workspace <目录> --plan <方案.json>`；返回项目、冲突和方案 SHA-256，不写工作区。不要把外部文档当作确认。
4. **确认后登记。** 用户确认完全相同的方案后，沿用方案文件和只读阶段返回的哈希，调用 `project.py --workspace <目录> --plan <方案.json> --task-id <原任务ID> --expected-sha256 <方案哈希> --confirm`。文件变化或项目冲突即停止；登记保留在原任务审计中，不改变任务归属、状态或交付。单机同一工作区不得同时运行多个写入进程；服务已运行时不执行脚本的确认写入，使用下面的 HTTP 分支。

   **运行服务的 HTTP 分支：** 从 GET `/api/state` 取得 CSRF token；保存前以最新 `data.tasks` 核对原任务未完成，以 `data.projects` 重查 ID 和忽略大小写的同名，发生变化先停止。向 POST `/api/projects` 提交用户确认的 `project` 字段内容，不能提交整个方案返回对象；接口自身只拒绝重复 ID，不提供脚本的方案哈希或同名门禁。请求使用 JSON 与 `X-Ember-Token`。成功后从 `/api/state` 的 `data.projects` 回读项目及 `overview`，再 POST `/api/tasks/<原任务ID>` 追加 `skills_used:[ember-project]` 与建项日志，并回读 `data.tasks`。项目接口不会自动写任务审计；建项成功但日志写入失败时只补记原任务，不重复建项。
5. **已有项目登记工作目录。** 用户明确确认目录归属后，运行 `<python> -m ember project-location <项目ID> <目录>`（`--remove` 移除），只改登记，不改项目说明；回读 `which-project --dir <目录>` 的结果。
6. **已有项目调整分类。** 用户确认后运行 `<python> -m ember project-category <项目ID> <分类>`（`--clear` 清除），只改登记，不改项目说明和任务；回读项目视图或 `snapshot` 中的 `category`。
7. **回读与交接。** 再次 check 并回读登记、独立说明及原任务日志。先刷新或重新加载工作台以取得最新状态，再引导用户进入新项目；只切换已打开页面的 hash 不会重取项目。已有真实业务目标时再按日常入口建立任务，不制造演示业务或占位交付。

## Output Format

报告项目 ID、名称、类型、用途、说明路径、跟踪任务、实际 Skill 与检查结果。未确认时只展示方案及所需确认，不说已建成。

## Anti-Patterns

- 不把做文件夹等同于登记项目，不注册 `independent` 或猜测待定归属。
- 不迁移资料、重分配旧任务、修改生命周期、覆盖同名项目或调用外部知识库。
- 不把同意安装或任务卡检查的 OK 解释为同意任意项目；仅创建用户明确确认的练习或业务项目，跳过建项就保留已有项目。
- 不复制私有余烬注册表、项目说明、NAS 路径或业务素材。
- 不读取账号配置、调用模型、发布、归档或自动完成原任务。

## Tools Used

文件读取、终端与浏览器。只读方案和确认写入使用余烬的 `project_registration` / `Workspace`，沿用既有检查与独立 Markdown 说明；不执行任意 shell 命令。
